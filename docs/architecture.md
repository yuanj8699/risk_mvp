# 本地测试版架构与下一阶段边界

## 当前业务范围

用户确认：我行下辖11个地区、82家行社；先监测行社，预留第4、5级机构。风险依据采用排名、占比、资金业务不良存在提醒。数据可以来自数据库与Excel，允许自建Python与数据库，可以调用小Q接口，最终嵌入内部风险管理系统。

本版将这些要求拆成五个相对独立的部分：

1. **机构与指标目录**：稳定ID、父机构、层级、单位、更新频率。
2. **数据接入**：文件或固定视图统一转成标准事实，校验后原子保存快照。
3. **规则检测**：对82家行社逐项执行适用规则，分别记录触发、未触发、数据不足、未配置。
4. **分析与函件**：选择辅助指标，读取同一快照证据，生成可编辑的通用测试函件。
5. **状态处理**：绑定函件修订进行审核、生成稳定的模拟回执和审计记录。

## 机构树

| level | 含义 | 本期是否监测 |
| --- | --- | --- |
| 1 | 我行/总行 | 否 |
| 2 | 地区 | 否，作为过滤与汇总维度 |
| 3 | 行社 | 是 |
| 4 | 支行 | 预留 |
| 5 | 待确认的下一级机构 | 预留 |

层级通过 `parent_id` 表达。以后新增支行时，需要支行粒度事实和对应比较规则，不能将行社指标复制给所有支行。示例中的支行和第五级记录只用于验证低层机构不会被误纳入本期监测。

## 数据粒度

测试版每个快照内，同一机构、同一指标只保留一个有效期次。跨快照可以保留同一指标不同期次的数据，也可以保留同一日期的修订数据。已经生成的事件保存当时证据，之后修改规则不回写旧事件。

未来若增加客户类型、业务类型等维度，需要将维度键纳入唯一约束，或将当前指标ID映射到明确的版本化度量定义。不要靠拼接中文名称模拟所有维度。

## 规则语义

排名条件暂为 `rank >= 72`，使用全省82家行社参评排名。完整无并列时命中11家，遇并列按条件命中。测试版种子排名已经给出，检测层不重排。

占比条件用“五级不良贷款率”展示输入方式，数值以百分数值保存：`1.65`代表`1.65%`。阈值为空时返回未配置，不产生默认发函依据。实际“不良贷款占比”的指标定义仍需确认。

存在提醒使用资金业务不良余额：有有效数据且值非零时触发。缺失不能转成零。比年初增量为负仅说明减少，不应被模板写成风险上升。

多条规则目前独立触发，再按行社归并；因此同一行社不会因为3项指标触发而在同次运行生成3封重复函。更复杂的AND组合、持续事件与跨期提醒频率属于后续规则能力。

## 模型接口

`AnalysisProvider.select(topic, indicators, mandatory_ids)`负责选择辅助指标，返回合法指标ID、理由和限制。无论返回什么，已启用的必查规则均由确定性检测执行。

`AnalysisProvider.explain(evidence, supporting)`负责形成事实、待核查解释、核查事项和限制。本版实现为明确标注的模板模式。小Q接口接入时，需要把真实请求协议、认证、流式/非流式返回与错误处理封装在新的provider中；没有接口文档前不假定其兼容任何第三方格式。

下一阶段接入真实模型时应验证：指标ID白名单、证据ID存在、最大补查次数、超时与退出条件、事实引用。模型可以提出关联分析，不能改写既有排名、阈值和发函对象。

## 函件与发送

草稿修订后回到待审核状态；旧版本不能被发送。审核绑定正文、证据与case。模拟发送只更新本地状态并生成稳定回执，不具备对外发送权限或接口。

真实风险管理系统对接时再实现：服务端身份、审批策略、目标机构映射、outbox、发送请求号、渠道幂等和结果查询。接口超时且结果未知时先查询/核对，不能仅因本地未保存成功就再次发送。

## 从原型到内网联调

建议按顺序推进：

1. 取得正式模板与机构编码映射。
2. 确认排名边界、占比定义/阈值、独立或组合条件。
3. 用少量经核对的脱敏事实对照现有报告，确认逐条证据。
4. 识别DataWorks实际数据源，建立只读标准视图或数据服务。
5. 接入小Q provider，固定同一批样例比较模板与模型的差异。
6. 加持久worker、接口鉴权、数据库迁移、日志与运行监控。
7. 对接内部风险管理系统测试环境，验证真实协议后再讨论自动下发范围。

当前SQLite验证结果不能当作PostgreSQL联调完成；本地模拟回执也不能当作内部系统已接入。
